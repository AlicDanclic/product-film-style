# 反例库

真实项目里踩过的坑，按「现象 → 原因 → 正解」记录。做新片前通读一遍，能省掉大部分返工。

## 一 · 切点与转场

**1. 硬切切到一张空卡片**
现象：段落切换后第一帧是空白卡片 / 只有边框，内容下一帧才开始长。
原因：段内入场动画从本地第 0 帧开始，而切点正好落在本地第 0 帧。
正解：把该段内容的时间轴整体前移。`const frame = useCurrentFrame() + ENTRY`，`ENTRY = 10` 起步。

**2. 前移了 10 帧还是空**
现象：结构简单的卡片正好了，但图谱、表格、节点连线类切点仍空一两帧。
原因：这类结构的入场本身分段进行（节点 → 连线 → 标签），10 帧只够第一步。
正解：按结构复杂度加码。经验值 22 帧（双节点 + 连线）、30 帧（表格首行已渲染）。稳妥做法是让切点落在「已经长了一半」的位置，而不是「刚好长完」。

**3. 列表 / 页面的入场切点也是空**
现象：面板外框（负延迟入场）解决了，但列表行和页面主体还是空的。
原因：两个子块的起点不同。
正解：让子块用**负起点**先于容器出现：`interpolate(f, [-12, 2], …)`、`[-16, 0]`。切点时它们已经接近终态。

**4. 段尾淡出 → 下一段切点白屏**
现象：全片每隔几段就闪一下白，约 0.27 秒。
原因：上一段结尾做了淡出，下一段又是硬切，两者相加等于「白 → 黑 → 白」。
正解：段尾一律不加淡出。全片只保留最后一次「进落版」的淡出交棒。

**5. 两个字幕叠加**
现象：落版画面出现两个版本号，一个在顶栏、一个在大标题里。
原因：上一层的元素还没退干净，下一层的就入场了。
正解：用两个错开的时序变量（`stageOut` / `outroIn`），让淡出在淡入前 10–12 帧就完成。任何「同一位置的新旧元素」都要这样做。

**6. 注释行在切点后孤零零一行小字**
现象：硬切后画面上只有右下角一行注释，看着像渲染故障。
原因：注释行从第 0 帧就全不透明，主体内容却还没入场。
正解：注释行延迟 34–46 帧淡入。

## 二 · 布局与安全区

**7. 字幕压住面板**
现象：底部那一行字和卡片下沿重叠。
原因：面板高度按「内容需要」定，没有反推安全线。
正解：先定 `CAPTION_TOP`，再按它反推内容高度上限（面板下沿 ≤ 890）。曾把面板上限从 820 压到 740 才让开。

**8. 面板高度算少了，内容被裁**
现象：面板底部被切掉一截，或最后一个区块压到下面的代码行。
原因：按各段高度之和算总高时漏算了段间 `gap`。
正解：总高 = Σ段高 + (段数 − 1) × gap + 内边距 × 2。算完再目检一次最底部那个元素。

**9. 元素撑破容器**
现象：一行放 11 个 tab，最后两个被截断或换行。
原因：字号和间距按「勉强够」估的。
正解：先算 `11 × (宽度 + gap) + 内边距 × 2 ≤ 容器宽`，再回填字号。压缩顺序：字号 → 内边距 → gap → 才考虑换行。

**10. 放大复用现有组件，出现空白和错位**
现象：把某个视图整体 `scale(1.4)` 放大后，画面一半空、节点互相压住。
原因：原组件是为小尺寸设计的，放大会同时放大它内部的留白和重叠。
正解：不为放大而放大。重画一版该尺寸的专用布局（例：自绘 1240×600），只复用配色和行结构。

**11. 泳道内文字不齐、条太细**
现象：同一行里名字、日期、状态各自基线不同；甘特条细得像铅笔线。
原因：用 `inline-block` 拼的，垂直对齐靠猜；条高取了 12–16px。
正解：行容器 `display:flex; align-items:center`，条高 ≥ 32。（实际用了 `BAR_H 34 / DAY 38`。）

**12. `alignSelf: flex-end` 不生效**
现象：按钮要贴右，写 `alignSelf` 没反应。
原因：父容器不是 flex，或该轴不是交叉轴。
正解：`marginLeft: 'auto'` + `width: 'fit-content'`，比 `alignSelf` 可靠得多。

## 三 · 时间轴与数值

**13. 渲染整帧崩掉，报 `inputRange` 非法**
现象：某一帧整帧渲染失败，控制台指向 `interpolate`。
原因：为了让某个值「永远不触发」，给它返回了 `Infinity`。
正解：用有限大数 `1_000_000`。任何进入 `interpolate` 的值都必须是有限数。

**14. 卡片装不下全部条目**
现象：15 行塞进固定高度卡片，最后几行溢出或被裁。
原因：卡片高度写死。
正解：高度 = 可见项高度之和 + gap 之和，随可见项数量**连续收缩**。观众看到的是卡片变薄，而不是内容变灰。

**15. 让位跟拖动进度绑成连续值，中间态糊成一团**
现象：拖动时空槽、幽灵、让位行三层重叠成一片。
原因：用连续进度插值兄弟行位移，任意中间帧都可能三方同框。
正解：让位必须**离散**——按「指针越过多少条中位线」算插入下标，兄弟行一次跳一格；幽灵是独立浮层只改 `transform`。这是复刻真实拖拽排序组件时最容易搞错的一点。

## 四 · 层级与指针

**16. 光标跑到画面右下角**
现象：鼠标图标出现在固定错误位置，不跟手。
原因：光标 JSX 放在了卡片容器里，用的是容器相对坐标，而坐标值是按舞台算的。
正解：光标、浮层这类「悬浮于一切之上」的元素，放在布局容器**之外**，直接用舞台绝对坐标。

**17. 幽灵盖住光标**
现象：拖动时鼠标图标消失，被拖的那一块盖在上面。
原因：幽灵 `zIndex: 5`，光标用的是默认层级。
正解：光标 `zIndex: 20`，所有内容层 `zIndex` 一律回 1。层级只留「内容 / 浮层 / 指针」三层，不要每块自己定。

## 五 · 事实与理解

**18. 讲错了产品逻辑**
现象：做出来的「功能对比」和真实产品对不上，用户一句「你好像理解错了」全部返工。
原因：凭功能名想象交互，没有去读源码。
正解：动笔前先读代码确认三件事——**有哪些项**（取常量数组）、**默认值是哪些**（取默认值数组）、**交互挂在哪**（搜 `use:` 指令 / 事件绑定）。README 也要读，但以代码为准；两者冲突时说明有历史遗留，按代码画并记录差异。

**19. 把「减法」拍成「升级」**
现象：新版删掉了图例、里程碑线、逾期标记，画面却一片喜气。
正解：删掉的东西要明写删掉了（`图例 · 里程碑线 · 逾期标记 —— 这一版都没有`），不要含糊成「优化」。

**20. 说过头**
现象：把「Worker 里跑插件」说成「安全沙盒」。
正解：能力边界要写清楚（`只做执行隔离与超时，权限与副作用仍归主线程 —— 不是安全沙盒`）。技术宣传片最常见的翻车不是画面，是承诺过大。

## 六 · 文案

**21. 分段说明越加越多**
现象：一开始每段只有一行标题，被要求「配点文字说明」后变成标题 + 副标题 + 三条要点，画面被挤满。
正解：加法解决不了「看不懂」。先检查是不是画面没讲清，再决定要不要加字；真要加，加在**画面上对应的位置**（字段名、函数名），不要加在底部说明区。

**22. 一句话里三个名词，观众读完画面已经走了**
现象：字幕停留 3–4 秒，但 12 个字的句子需要 5 秒才读完。
正解：按「每秒 4–5 个汉字」估字幕停留时长。超了就拆段或删字，不要缩短停留。
