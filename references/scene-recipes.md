# 镜头配方

九种镜头覆盖了这种风格里的绝大多数情况。每种给「用在哪 / 构图 / 时序 / 易错点」，可以直接照做。

---

## 1 · 品牌开场

**用在哪**：全片第一个镜头，主片与对比片共用同一套。

**构图**：居中。品牌标记（几何图形，尺寸约 120–160px）→ 产品名 84–110px / 800 字重 / 字距 −4 → 其中一段词走品牌渐变。下方留版本号或定位句，与字标间距 40–56。

**时序**

| 帧 | 动作 |
|---|---|
| 0–18 | 标记 spring 入场（scale 0.86 → 1，无回弹） |
| 12–40 | 产品名逐字符升起，每字间隔 2 帧 |
| 30–48 | 渐变词的渐变色相位开始移动 |
| 40–70 | 版本号 / 定位句淡入 |
| 70–150 | 静止，只留常驻微浮动 |

**易错点**

- 首帧黑屏或白屏是正常的（片头从无到有），但**第 1 帧就要有背景**，不能是纯色
- 产品名逐字符进场时，每字的 baseline 要一致——用 `translateY` 不用 `top`
- 不要在这一段加副标题。「一句话介绍产品」在这里出现会显得心虚

---

## 2 · 界面首亮相

**用在哪**：主片第 2 段，让观众第一次看到产品长什么样。

**构图**：`APP 1480×840` 整体居中略偏上（下沿不越过 890）。外层 `SHADOW.window`，圆角 18，无边框。

**时序**

| 帧 | 动作 |
|---|---|
| 本地 0–20 | 窗口从 scale 1.06 / translateY 60 / rotateX 7° 归位 |
| 20–34 | 侧栏、顶栏先就位（它们是骨架） |
| 30–90 | 主区内容按 12 帧 stagger 逐块出现 |
| 90+ | 启动 sin ±5px 常驻浮动 |

**易错点**

- `perspective(1500px)` 必须加在**父容器**，加在自身无效
- 常驻浮动不要在入场的同时启动，两段位移会打架
- 首亮相不要演示交互，此时观众还在认界面

---

## 3 · 痛点三连

**用在哪**：主片第 3 段，三个具体麻烦 → 压一句主张。

**构图**：三张卡片横排（每张约 420×220，间距 40），或三行竖排。下方留主张大字（84px）的位置。

**时序**：卡片 0/12/24 帧依次弹入 → 停留 40 帧 → 卡片**彻底淡到 0** → 主张大字在空出来的位置升起。

**易错点**

- 卡片退场必须是 `exitStyleHard`（淡到 0），不能用默认的上飘淡到 10%——它们正压着大字的位置，透出来就是叠字
- 三张卡片的文案要同构（都是「你做过什么 + 结果多糟」），不要一张长一张短
- 主张大字只有一句，不要排比

---

## 4 · 清单收窄（N → M）

**用在哪**：讲「默认值变了」「功能可以关掉」这类改动。对比片最常用。

**构图**：左右两栏。左栏是选项清单（两列，每项一行：开关 + 名称），右栏是**真实界面**跟着一起塌缩。顶部放计数角标 `N / N → M / N`。

**时序**

| 帧 | 动作 |
|---|---|
| 0–30 | 清单与界面同时就位（界面可以先出现，用负起点） |
| 44–90 | 每 12–15 帧关掉一项，被保留的项不动 |
| 每关一项 | 界面里对应区块**塌缩消失**，界面高度连续收缩 |
| 90–120 | 落下一行结果（如 `simple: ['title','status','due_date']`） |

**易错点**

- 关掉的项要**真的消失**（`display:none` / 高度归零），不是变灰留位。变灰是「禁用」，不是「关掉」
- 界面高度必须随塌缩连续收缩，否则中间会出现大片空白
- 计数角标要与实际开关数量联动，手写数字一定会对不上
- 标签页类的收窄用**宽度归零**（不是变灰），读者才看得出「少了一个」

## 5 · 拖拽排序

**用在哪**：演示指针拖拽类交互。

**构图**：列表卡片约 940 宽，行高 72，行内从左到右：抓手（14px 六点，默认 opacity 0，hover 0.7）→ 多选框 22×22 → 圆形完成框 20 → 颜色点 8 → 标题 → 优先级胶囊 → 标签 → 日期 → 角标 → `⋯`。

**时序**（以 240 帧一段为例）

| 帧 | 动作 |
|---|---|
| 10–30 | 光标移入 |
| 28–36 | 按下（行抬起：白底 + 大阴影 + scale 1.02） |
| 40–52 | 抬起离开原位，原位置变成 opacity 0.28 的空槽 |
| 52–112 | 匀速下移；指针越过某行中线时，该行**瞬时**让位一格 |
| 112–132 | 松手，空槽补进目标位 |
| 132–146 | 幽灵淡出 |
| 146–200 | 新位置高亮一次（`inset 0 0 0 1.5px`） |

**易错点**

- **让位必须离散**。绑连续进度会让空槽、幽灵、让位行三者同时出现在中间态，糊成一团
- 幽灵是 `cloneNode` 式独立浮层，只改 `transform`，不要和空槽共用元素
- 光标要放在布局容器**之外**、用舞台绝对坐标，`zIndex` 高于一切
- 空槽的 `zIndex` 返回 1，靠 DOM 顺序自然遮挡

## 6 · 画布绘制

**用在哪**：演示「可以画」类能力（甘特图、排期、白板）。

**构图**：满幅画布，泳道行高 106，日格 38，条形高 34。左侧泳道名 240 宽。顶部时间刻度。

**时序**

| 帧 | 动作 |
|---|---|
| 40–70 | 光标从空白处按下并横向拖出幽灵框 |
| 70–80 | 松手，幽灵框变实心条（例：4 天宽） |
| 90–120 | 再画一条（6 天），走同一套动作但缩短 |
| 130–170 | 按住第一条整体右移 7 天 |
| 170–200 | 拉右端加长到 6 天 |
| 200–240 | 底部两行短提示（「空白处横向拖一下，就多一条」） |

**易错点**

- 泳道内文字要 `display:flex; align-items:center`，不要用 `inline-block` 猜基线
- 条形高度低于 32 会细得像铅笔线
- 拖出的幽灵框和最终实心条必须**同宽同高**，否则像两个不同的东西
- 提示语最多两条，多于此就变成教程

## 7 · 左右对照

**用在哪**：一支片子里最需要说服人的那一处。全片只有一处。

**构图**：双面板，各自 860–900 宽，左旧右新，中间留 40–60 间距。面板顶 `DUAL_TOP = 222`，下沿 ≤ 890。面板上方各放一枚版本号角标。

**时序**：左面板先就位（0–20）→ 右面板略迟 6–10 帧 → 两边同时开始演化 → 差异处用**同一时刻**的两个不同结果呈现（不是先后演示）。

**易错点**

- 两边的**行高、字号、列宽**必须取自各自源码的真实值，即使两版不同——差异本身就是内容
- 差异不要用红框圈出来，让画面自己说话；实在需要，用一句面板内的注释说明（新版的删减项）
- 不要两边各说各话。左右对照的目的是「同一件事的两个结果」，不是「两个产品的介绍」

---

## 8 · 节点 + 连线

**用在哪**：架构、数据流、执行位置这类抽象关系。

**构图**：2–3 个节点 + 连线。节点用卡片（约 200×90，圆角 14，`SHADOW.pill`）；连线用贝塞尔，锚点取节点边缘。

**时序**：节点 12 帧 stagger 入场 → 连线按路径长度 20–24 帧生长 → 线上标签最后出现 → 需要强调的那一段（如 Worker 框）用虚线框罩住并倒计时。

**易错点**

- 节点与连线必须共用**同一套像素坐标系**：SVG 不要设 `viewBox`，直接用绝对坐标，否则缩放后连线会错位
- 贝塞尔控制点收在节点间距内，否则连线会回头穿过节点
- 依赖箭头起点用「排他结束时间」，不要用结束时间，否则箭头压在任务条内部
- 抽象关系图里最多 3 个节点，第 4 个开始观众记不住

---

## 9 · 落版

**用在哪**：全片最后。

**构图**：居中偏上。一句结论（56–72px / 700）→ 一行补充（22px / 500 / 次要色）→ 授权与价格 → URL（等宽 / 22px / `#6F7281` / 上间距 24）。

**时序**：顶栏版本号先退干净（−12 帧开始）→ 12 帧后结论升起 → 24 帧后补充行 → 40 帧后 URL → 之后静止。

**易错点**

- 同一位置的新旧元素必须错开时序，否则出现两个版本号叠印
- URL 前面带 GitHub / 官网图标时，图标与文字要垂直居中，不要 baseline 对齐
- 落版之后不要再加「感谢观看」「记得点赞」这一类
